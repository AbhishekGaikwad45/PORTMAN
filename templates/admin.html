Uninvoice — remove invoices with no SAP document

        

            Lists invoices that were generated but have no SAP document number (never posted to SAP).
            Uninvoicing deletes the invoice — freeing its number so the series continues with no gap —
            and resets its bills from Invoiced back to Approved so they can be re-invoiced.
            Cargo and bills are left intact. Invoices that already have a SAP document must be cancelled via FINV01 instead.

Remove Bill — delete duplicate / unwanted bills

        

            Lists bills that are not invoiced. Removing a bill deletes it —
            freeing its number so the series continues with no gap — and releases the cargo/service billed
            tracking it held, so those items become billable again. Invoiced bills are not shown; uninvoice
            them first (Uninvoice tab), which returns them here as removable.
            An Approved bill can instead be sent back to Draft: the bill and its
            number are kept, the approval is cleared, and it becomes editable again.

Release Cargo — make wrongly-billed cargo billable again

        

            Last resort for cargo billed to the wrong customer on an invoice that
            already reached SAP, where Uninvoice and Remove Bill are both refused. Releasing clears
            only the billed tracking on that one cargo line, so it can be billed to its rightful
            customer. The bill, the invoice and the SAP posting are left exactly as they
            are — correct the money with a credit note (FDCN01), never by rewriting an
            issued invoice. Every release is written to the approval log.
        

        

            If the invoice has no SAP document number, do not use this — Uninvoice then
            Remove Bill is the clean path and it frees the cargo for you.

Swap Bill Cargo — replace wrong cargo without moving the money

        

            For a bill that ended up charging one customer for another customer's cargo.
            Pick the offending line and replace it with cargo belonging to the bill's own customer.
            The replacements inherit the removed line's rate and must add up to the
            same quantity, so the bill total, the invoice total and the SAP posting
            are provably unchanged — only which cargo backs the charge moves. The displaced cargo is
            released and becomes billable to its rightful customer.
        

        

            Safe on an already-invoiced bill: the swap is refused outright if it would change any
            total, or if the matching invoice line cannot be identified beyond doubt. If you need the
            amount to change, that is a credit note (FDCN01), not a swap.
